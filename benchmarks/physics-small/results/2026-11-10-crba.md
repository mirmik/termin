# Small-system CRBA results — 2026-11-10

First measured optimization for #3764: replace mass-matrix construction by N full RNEA calls with CRBA. Integration, tolerances, contact model and solver checks are unchanged. The inverse-dynamics RNEA implementation remains an independent numerical oracle.

## Method

AMD Ryzen AI MAX+ 395, Linux x86-64, CPU affinity 0; Release (`-O3 -DNDEBUG`). Baseline runtime source: `8e9368e6e`; after: that revision plus the CRBA patch in this working tree. Both SDK versions were built using `TERMIN_PYTHON_RUNTIME_OFFLINE=1 task build`. Only the robotics library hash changed among the four measured SDK libraries; base, QOpt and physics-QOpt hashes are identical. Native benchmark source hashes match.

1000 steps at dt=0.001 s per trial, one warmup and seven measured trials. Each trial starts from the same model/state. Timing excludes model construction; the complete model and case definitions are in [the benchmark README](../README.md). CPU affinity differs from the preliminary unpinned timings in the original card; compare the paired measurements below.

```sh
TERMIN_PYTHON_RUNTIME_OFFLINE=1 task build
task benchmark:physics-small -- --cpu 0 --sdk-build-cache build/Release/CMakeCache.txt --output build/benchmarks/physics-small/results.json
task test -- --no-python
```

Raw measurements, all samples, numerical outputs and SDK hashes: [before](2026-11-10-before.json), [after](2026-11-10-after.json). The before run predates the optional SDK-cache field; its compiler flags above were read from `build/Release/CMakeCache.txt`. The after JSON also retains that cache. The runner labels SDK/checkout correspondence unverified; the explicit paired SDK builds and library hashes provide the provenance for this experiment.

Before optimization, the separate instrumented 24-DOF trial spent 145.53 µs of 230.30 µs (63.2%) assembling contributions that rebuild M. After optimization that stage takes 19.70 µs of 105.68 µs. These stages include bias and block assembly as well as M; fixed-configuration kernel timings in the table are measured separately. Both versions rebuild M exactly twice per step.

Remaining measured costs at 24 DOF: cached-M assembly 13.83 µs, velocity updates 15.22 µs, configuration updates 2.21 µs; the remaining approximately 54.72 µs includes QP solves, validation, lifecycle work and instrumentation. This residual is not an isolated factorization timer. Bias counts and endpoint factorization/reuse counts are unchanged.

The unchanged contact/friction solver measures 11.58 → 11.78 µs in these runs (~1.7% variation); its numerical result is identical. The bias kernel is also unchanged and slightly slower in the after run. No speedup is claimed for either; frequency/thermal and concurrent-work effects remain possible despite fixed affinity.

## Numerical verification

| DOF | Max abs initial M difference | Max abs final q difference | Max abs final v difference |
| --- | ---: | ---: | ---: |
| 2 | 0 | 0 | 0 |
| 6 | 2.66e-15 | 1.78e-15 | 1.27e-14 |
| 12 | 7.11e-15 | 3.39e-14 | 5.36e-13 |
| 24 | 9.95e-14 | 2.09e-13 | 3.37e-12 |

Initial nonzero-velocity bias arrays match exactly. All throughput repetitions are deterministic within each build; instrumented and uninstrumented final states match exactly within each build. Floating/branched models are covered by regression tests, not by the throughput table.

`task test -- --no-python` passed 271/271 CTest registrations, including robotics oracles, multibody energy/momentum, contact/friction, rollback and FEM. The initial sandbox run failed only three loopback-service suites; the final run with loopback sockets allowed passed. Both full SDK builds passed, including native-extension ABI/import checks. Python test suites and Windows execution were not run.

New oracles compare every mass-matrix column and a dense acceleration vector with `ID(v,a,g) - ID(v,0,g)`, and compare `0.5 vᵀ M v` with kinetic energy. Coverage includes multiple states, branching/multiple roots, revolute/prismatic joints, offset/rotated inertias, fixed/floating bases and a base-only model. Invalid parent/self-cycle models fail with a diagnostic before traversal.
