# Six-foot spider step throughput

The Termin scene at `termin-spider-control@b2ccb29` and its MJCF export at
`twister-capper@227a485` have 28 DOFs. The matched experiment lands the robot,
moves one hip target by 5 degrees and returns to its starting stance. The
comparison uses the first 1000 steps to settle the robot and times the next
3000 steps at dt = 1 ms. The Termin entry point updates the physics-only scene.
The MuJoCo entry point sets the actuator control, runs mj_step and refreshes
end-of-step kinematics. Startup, rendering, observation and trace writing are
outside the timed blocks.

Linux x86-64, Ryzen AI MAX+ 395, logical CPU 2, Release SDK based on
`2b402a7dc`, MuJoCo 3.15.0. Each column is an independent process. Times are
the mean wall-clock microseconds per step in each run.

| Termin with friction response cache and simplified convexity check | 815.7 | 816.5 | 816.0 |
| Termin also using previous support rows | 494.7 | 492.7 | 500.0 |
| MuJoCo | 12.6 | 11.4 | 11.4 |
| MuJoCo with 10 NoSlip iterations | 13.4 | 13.4 | 13.4 |

Before the change, six supporting feet required 18 response solves with the
same mass matrix and bilateral Jacobian. Reusing one factorization within that
loop gave 897 µs/step in an intermediate run. The 816 µs result also removes
the trivial minimum-norm solve for zero equalities and simplifies the
convexity check in the active-set solver. The four-second Termin traces before
and after those two changes agree exactly at all 4001 samples for body and foot positions, joint
coordinates, applied torques and target commands.

In the CPU profile at 816 µs/step (1239 samples), 59.5% of stacks include the active-set
QP solver and 47.9% include unilateral velocity projection. These shares overlap.
The matched experiment in twister-capper measures maximum foot displacement at
0.142 mm for Termin, 17.22 mm for standard MuJoCo and 0.136 mm with NoSlip 10.

## Reusing the supporting contacts

Position and velocity projection now try the previous supporting rows as
equalities with the current M, Jacobian, load and limits. Success requires
the full QP optimality checks. The regular solver handles a newly blocking
or released contact, and resolves load sharing on degenerate faces.

On steps 1000–3999 of the 1 ms sweep the instrumentation gave these counts.
Phase I finds a feasible point for the active-set search. The velocity column
includes both configuration passes.

For landing, on steps 101–199, position and velocity projections together
went from 297 Phase I calls to two. These counts were taken in separate

At 0.5, 1 and 2 ms the maximum absolute differences from the reference

plane of a foot, was typically 38 µm there and reached 326 µm on landing.
This includes a physical configuration change. The experiment below tests reuse after this correction.

## Checking the first solution at the corrected configuration (#3939)

At each second friction solve, a separate probe retained the preceding pass's
final velocity and impulses. It checked the momentum residual on the updated
matrices and base normal projection. With new inputs, the required balance is
`M (v − v_base) = Jnᵀ (p_n − p_base) + Jtᵀ p_t + Jbᵀ p_b`.
The probe also checked supporting normal velocities, all normal inequalities
and the friction polygon, and computed each foot's friction work using the
updated tangent rows. The true second solution served as a positive control.
These are necessary conditions for reuse.

Five independent four-second, 1 ms runs covered the normal sweep, constant
targets, the two lift commands above, and sliding (same sweep, world friction
coefficient reduced to 0.15). Across 19,495 paired solves, zero first-pass
solutions and all 19,495 second-pass solutions passed the numerical checks.
During static hold, the median carried momentum residual was 2.43e-6 and the
normal velocity residual was 8.57e-7 m/s, each with tolerance 2e-9. The cone
and dissipative total work alone accepted the carried outputs. On landing,
the maximum per-foot changes in normal and tangential impulse were 2.12e-4
and 1.56e-4 N·s; the maximum per-foot work difference on the updated geometry
was 4.22e-5 J. The reference recorder produced identical arrays with the probe
enabled. Both configuration passes remain in production.

The accepted optimization reuses work *within* each cold QP on its current
inputs. Its equality-constrained objective minimizer already certifies
equality feasibility and reduced curvature. If every inequality is slack,
the solver checks the full KKT residuals directly on that minimizer. This
avoids solving the same problem again with an empty working set.

## Batching unit contact impulses (#3947)

Each friction pass assembles one column for each foot's normal and two tangent
directions. All columns share the current mass matrix and bilateral Jacobian.
The scalar baseline already reused their factorization. The batch also reuses
the validated and normalized coefficients, bypassing repeated matrix copies,
cache comparisons and dynamics wrapper calls. It applies the same spectral
rank tests and checks each column's residuals before publishing the response
matrix. The second configuration gets its own batch.

Five alternating pairs of fresh processes on CPU 2 compared the installed
libraries at `5ede4ee99` with this change, using the 1 ms protocol below.
Full-step time decreased by 19.2%. The original 1574.3 µs baseline and the
current 353.38 µs median differ by a factor of 4.45 across all optimizations.

## Certifying full-rank mass matrices (#3948)

For a response batch with zero bilateral rows, the spectral solver uses a
curvature cutoff of `abs_tol + rel_tol * max(1, max_abs_eigenvalue)`. The new
path first tries Cholesky on a copy of the symmetrized mass matrix with a
diagonal shift above that cutoff. It uses the matrix one-norm to bound the
spectral radius and adds a floating-point error margin. A successful shifted
factorization certifies all mass directions, including those absent from the
contact loads. A second Cholesky factorization solves the original system for
all columns. Each column must meet its own stationarity tolerance. Uncertain
rank, failed residual checks and batches with bilateral rows use the spectral
solver.

Five alternating pairs on CPU 2 compared the spectral batch at `74b8210b2`
with the Cholesky batch. Each process timed 3,000 loaded steps at 1 ms after
1,000 settling steps.

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Spectral | 350.27 | 348.62 | 350.97 | 350.13 | 349.23 | 350.13 |
| Certified Cholesky | 309.89 | 309.75 | 310.36 | 309.88 | 310.18 | 309.89 |

On this workload, that saved 40.24 µs per full step (11.5%). MuJoCo NoSlip 10
measured 13.46, 13.49 and 13.39 µs/step (median 13.46).

On CPU 7, replaying 60 captured matrices (1,080 response columns) through
the installed libraries took 27.04 µs per spectral batch and 7.94 µs per
Cholesky batch. In separate instrumented runs, the eigensolve took 19.60 µs,
the shifted factorization and certificate took 1.25 µs and factorization of
the original matrix took 0.99 µs. All 60 matrices passed the certificate.

On the seven stable four-second runs (0.5–2 ms), the largest difference in any
foot position was 7.11e-14 m. Loaded contact masks and the three liftoff times
matched. Maximum displacement in the low-friction run was 61.64513 mm for
both solvers.

At 5 ms both builds fell: body height first crossed 0.8 m at 2.575 s. Foot
positions differed by more than 1 µm at 2.560 s, 1 mm at 2.695 s and up to
0.411 m during the subsequent tumble. Across 59,972 calls on identical inputs
from all eight runs, both solvers reported the same rank and status. Maximum
differences in normal and tangential impulses were 1.43e-13 and 2.56e-13 N·s,
and per-foot work differed by at most 3.89e-13 J. Substituting the spectral
batch responses into the new binary reproduced all 801 baseline samples
exactly at 5 ms. This ties the post-fall divergence to amplification of
roundoff in the two equivalent mass solves.

A separate replay used 1,000 manufactured systems with rotated eigenspaces,
varying scales and eigenvalues around the rank cutoff. All reported ranks
agreed. On six full-rank inputs Cholesky satisfied the unchanged residual
test where the spectral solver returned `ResidualTooLarge`. The other 994
statuses and diagnostics matched.

With the friction response optimization alone, the integrator still factored
the 28×28 mass matrix for the initial acceleration and at two endpoint
configurations per loaded step. The three eigendecompositions took 63.46 µs
on CPU 9. The acceleration solver now uses the same full-rank certificate,
retaining the unshifted Cholesky factor for successive loads at an endpoint.
The scoped cache checks the coefficients and tolerance on each reuse.

Five alternating triples of processes on CPU 2 isolated this change. The
medians for the spectral baseline, improved contact responses, and contact
responses plus accelerations were 348.29, 310.73 and 258.22 µs/step. On a
replay of 216 acceleration loads from 30 steps, both solvers reported the same

One initial solve went from 21.51 to 4.23 µs, a fresh endpoint solve from

The first 100 ms of the 1 ms run also retained the same maximum height error

## Contact motion queries and the initial friction solve (#3952–3954)

The comparison starts from `84fb75230`. Registration, contact persistence,
error checks and post-solve telemetry now read a material point's world
position and velocity through a lightweight query. On the loaded spider
this avoids building an unused Jacobian and bias acceleration in about 72
of the 102 articulated point queries per step. Assembly still requests the
full Jacobian for normal and friction constraint rows.

In the 1 ms sweep the initial equality-constrained minimum of the friction
objective satisfied all inequalities in 6,000 of 6,000 measured calls. For
independent support equations and a well-separated positive-definite Hessian,
the active-set solver now obtains this minimum with a Schur complement. The
rank test uses the Gram matrix of the normalized equality rows. An
inconclusive rank certificate or an excessive residual selects the spectral
solver. The active-set solver still checks the inequality constraints for
each problem.

Profiling both friction passes on CPU 7 with the lightweight point queries
enabled, the time spent finding this initial minimum fell from 24.90 to
7.94 µs/step. The entire friction solve fell from 65.14 to 47.67 µs/step.

Five alternating triples on CPU 2 measured the full uninstrumented step
with 1,000 steps of warm-up and 3,000 loaded steps per process.

## Repeated mass assembly and factorization at be51146a7 (#3956, #3957)

During the 3,000 measured steps the spider's articulation contributed its
28×28 mass block 30,532 times. Its existing cache served 18,532 of those
requests. Four configurations per step still triggered a composite rigid-body
mass calculation. In five instrumented runs on CPU 6 these four calculations
took 17.33 µs/step in total. Adding all mass blocks to the global matrix took
another 3.27 µs/step. On all 2,999 boundaries between measured steps the
initial matrix matched the preceding final matrix bit for bit. The unconditional
invalidation in `begin_step()` accounts for one extra calculation per step.

At either contact configuration, endpoint acceleration, normal velocity
projection and friction response received identical mass coefficients. This
held for all 59,970 friction calls in the eight four-second trajectories.
The two contact configurations *within* each loaded 1 ms step had different
matrices on all 3,000 steps.

For these four distinct matrices the QP library computed eight ordinary
Cholesky factors of M and eight shifted factors to certify rank per step.
Counting only these 28×28 operations on CPU 9 gave 8.24 µs/step for the
ordinary factors and 10.27 µs/step for the certificates and their preparation.
Acceleration used absolute and relative tolerances of 1e-12, while normal
projection and friction used 1e-9. The ordinary factor depends only on the
coefficients. The certificate also depends on the required threshold.
The 18×18 friction objective and 6×6 Schur complements are separate systems.

Two benchmark-only variants measured the available savings. The articulation
variant checked joint coordinates on each mass cache read, kept the existing
invalidations on trial configuration changes and rollback, and retained the
accepted matrix across the step boundary. Actual mass calculations dropped
from four to three per loaded step. A direct call to assemble after an
external joint change also exposed a stale entry in the original implementation
(M[0,0] was 2.622003 instead of 2.363373). Checking the cache on access
corrected that case. The QP variant kept the last exact mass matrix within the
step, sharing its ordinary factor across tolerances and its certificate at
identical tolerances. It eliminated four ordinary and two shifted factors per
loaded step. Both variants used temporary libraries for one spider.

## Reproduction

Place all three checkouts side by side. From the Termin root, save the following
driver as `/tmp/time-spider.py`. It reuses the reference experiment's scene,
controller and step callbacks.

```python
import argparse
import sys
from pathlib import Path
from time import perf_counter_ns

sys.path.insert(0, str(Path("../twister-capper/scripts/spider").resolve()))
import run


def measure(args, joints, advance, observe):
    commands = [run.command(i * args.dt) for i in range(4000)]
    for angle in commands[:1000]:
        advance(angle)
    observe()
    elapsed = 0
    for start in range(1000, 4000, 100):
        batch = commands[start:start + 100]
        begin = perf_counter_ns()
        for angle in batch:
            advance(angle)
        elapsed += perf_counter_ns() - begin
        observe()
    print(f"{elapsed / 3000 / 1000:.2f} us/step")


run.record = measure
engine, noslip = sys.argv[1:]
args = argparse.Namespace(dt=.001, scene=run.SOURCE, model=run.MODEL,
                          noslip_iterations=int(noslip))
(run.run_termin if engine == "termin" else run.run_mujoco)(args)
```

```sh
taskset -c 2 sdk/bin/termin_python /tmp/time-spider.py termin 0
taskset -c 2 ../twister-capper/.venv/bin/python /tmp/time-spider.py mujoco 0
taskset -c 2 ../twister-capper/.venv/bin/python /tmp/time-spider.py mujoco 10
```

For a full trajectory, use the reference recorder before and after rebuilding.

```sh
sdk/bin/termin_python ../twister-capper/scripts/spider/run.py termin /tmp/spider.npz --dt .001
```
