# Пограничная служба

У Core есть простой тест на гражданство: может ли сущность существовать без
графики, мешей, assets, сцены, физики, редактора и конкретного platform host?

Если ответ требует длинного монолога и схемы с камерой, заявка уже выглядит
подозрительно.

## Что здесь уместно

Хороший кандидат в Core:

- нужен нескольким независимым верхним доменам;
- выражается через нейтральные данные или language boundary;
- тестируется без engine lifecycle;
- не требует GPU, window system, scene graph или asset database;
- имеет смысл как часть установленного SDK;
- не тащит за собой половину города.

Именно поэтому здесь есть `Vec3`, dispatcher и inspect contract. Они ничего не
знают о том, кто ими пользуется.

## Что остаётся снаружи

Core не принимает зависимости на:

- Graphics: images, meshes, shaders, GPU и UI;
- Physics;
- Engine: assets, scenes, components и runtime policy;
- Editor и player;
- Platform hosts.

Запрет относится не только к линковке. Нейтральный модуль, внутри которого
спрятаны понятия `active_scene`, `selected_entity` или `render_device`, уже
перешёл границу, даже если заголовок назван `generic_context.hpp`.

MCP server может исполнить запрос через переданный host context, но Core не
объявляет, что в context обязана быть сцена. Orbit camera считает pose, но не
знает, какой renderer применит матрицу. Log queue принимает записи, но не
решает, какая editor console их покажет.

## Граница физическая, но не отдельная

Пакеты лежат под `core/`, однако этот каталог не является build root. Корневой
CMake добавляет Core как нижний слой общего графа, корневой Taskfile строит
профили, корневая CI проверяет результат.

Внешний consumer видит только установленный SDK. Никаких
`../termin/core`, `add_subdirectory()` чужого checkout или «временно найдём
header в source tree». Видимость всех исходников в монорепозитории не является
разрешением на незаявленную зависимость.

## Вопросы перед переносом кода

Перед тем как опустить utility в Core, полезно спросить:

1. Какие два независимых нижних потребителя уже нуждаются в нём?
2. Как выглядит контракт без терминов верхнего домена?
3. Кто владеет памятью, callbacks и shutdown?
4. Может ли installed consumer проверить его без исходников Termin?
5. Не превращаем ли мы Core в склад «общего», которое просто некуда положить?

Если ответы ясны — люк открыт. Если нет, код почти наверняка лучше понимает
собственный домен, чем мы готовы признать.

Нормативное направление зависимостей находится в
[District monorepo ADR](../../architecture/2026-08-14-district-monorepo.md).
