1. Граница рассмотрения и термины

Начальная точка документа — narrow phase уже вернул ColliderHit с отрицательной дистанцией. Broad phase (BVH/AABB) здесь нужен только для контекста: он даёт пары, но не контактную геометрию. Конец пути — создание контактов игрового импульсного решателя либо передача Contact3D в qopt и сборка односторонних строк.

Manifold или patch? Канонический C++ тип сейчас — ContactPatch. Заголовок contact_manifold.hpp является только compatibility include. Старое слово «manifold» ещё живёт в комментариях, именах локальных переменных и C API. Это не библиотека termin-thirdparty/manifold: та относится к CSG/мешам.
ПонятиеСмысл в текущем коде
ColliderHitОдин результат narrow phase: две точки, нормаль A→B и signed distance.
ContactCandidateОдна solver-neutral пара контактных точек в world space, signed gap и необязательные feature IDs.
ContactPatchОдна пара коллайдеров, общая нормаль и сокращённый набор кандидатов (обычно ≤ 4).

2. Общий конвейер

CollisionWorld::detect_contacts() выбирает пары через BVH либо наивный двойной цикл и вызывает test_contact_pair(). Patch создаётся только при hit.distance < 0, затем всегда проходит общий reducer. См. collision_world.cpp:73–122.

3. Вход: подтверждённый ColliderHit

Контракт narrow phase задаёт:

n = normal(A → B),   d = distance,   collision ⇔ d < 0

Вместе с n возвращаются pA и pB — точки на соответствующих коллайдерах. Определение находится в collider.hpp:35–45.

Источник hit зависит от пары:

  • box-box: SAT по 15 осям; минимальный overlap становится глубиной δ, а d = −δ — box_collider.hpp:275–342;
  • convex hull и пары через support mapping: GJK подтверждает пересечение, EPA даёт нормаль, глубину и барицентрически восстановленные точки — gjk.cpp:308–392, 466–489;
  • sphere/capsule и смешанные примитивы: аналитические closest-point формулы.

Дальше collision layer нормализует результат в единый геометрический контракт кандидата:

g = n · (pB − pA),   g < 0 — penetration,   p̄ = ½(pA + pB)

Он записан непосредственно у ContactCandidate: contact_patch.hpp:28–47.

4. Генерация контактных кандидатов

Все пары, кроме box-box

Путь прямой: ColliderHit превращается ровно в один ContactCandidate. Обе точки и signed distance копируются без потери; feature IDs остаются INVALID_FEATURE. Реализация: collision_world.cpp:97–122.

Box-box: Sutherland–Hodgman clipping

  1. На A выбирается reference face с максимальным arg maxf∈faces(A) nf · n
  2. На B выбирается incident face с минимальным arg minf∈faces(B) nf · nref
  3. Четыре ребра reference face задают внутренние clip-полупространства sk(x) = qk · x + ck ≤ 0
  4. Incident quad последовательно обрезается каждой плоскостью. Для пересекающего плоскость ребра a→b: x = a + t(b−a),   t = s(a) / (s(a) − s(b))
  5. Для каждой оставшейся вершины p считается signed distance до reference plane: dref = nref · p + cref Берутся только точки с dref < 0.
  6. Строится пара endpoints: pB = p,   pA = p − n dref,   g = dref

Выбор граней и clip-плоскостей: collision_world.cpp:180–249; сам clipping: 251–290; сбор кандидатов: 292–376.

Feature identity кодируется как feature_a = ref_face и feature_b = (incident_face << 16) | clipped_index. Если clipping не дал ни одной точки, используется одиночный ColliderHit.

5. Построение сокращённого набора

Reducer solver-neutral и применяется к каждому patch независимо от его происхождения. Значения по умолчанию: максимум 4 точки, duplicate tolerance 10⁻⁹, tolerance сравнения метрик 10⁻¹². Конфигурация: contact_patch.hpp:60–65.

5.1. Канонизация и dedup

Кандидаты сначала сортируются по (signed_gap, feature_a, feature_b, pA.xyz, pB.xyz). Поэтому первый элемент — самый глубокий (наиболее отрицательный gap), а результат не зависит от порядка обхода BVH или clipping.

Два кандидата считаются дубликатами, только если близки обе endpoint-точки:

‖pA,i − pA,j‖² ≤ ε²   ∧   ‖pB,i − pB,j‖² ≤ ε²

Код сортировки и dedup: contact_patch.cpp:12–57, 107–143.

5.2. Проекция в контактную плоскость

Для spatial coverage берётся midpoint и удаляется нормальная компонента:

mi = ½(pA,i + pB,i),   qi = mi − n(n · mi)

Нормаль предварительно нормализуется; при почти нулевой нормали используется +Z. Проекция сохраняет расстояния в контактной плоскости и делает выбор инвариантным к общему rigid transform сцены.

Результат: collision layer отдаёт небольшой, детерминированный набор с приоритетом глубины и пространственного покрытия. Он не хранит impulses, active set или warm-start state — это политика потребителя.

6. Потребитель №1: классический PhysicsWorld

На каждом fixed step мир синхронизирует позы, вызывает detect_contacts(), отбрасывает пары без динамических тел и static-static, а затем разворачивает каждую точку patch в отдельный physics::Contact:

contact.point = ½(pA + pB),   contact.normal = n,   penetration = −g

Адаптация находится в physics_world.cpp:115–139. Последовательность step — forces → collision → solve velocities → positions → position correction: 66–81.

Что решатель делает с контактом

Для направления d (нормали или tangent) вычисляется скалярная effective mass:

w(d) = Σbody∈{A,B} [m⁻¹ + d · ((Iworld⁻¹(r × d)) × r)],   Meff(d) = 1 / w(d)

Нормальная относительная скорость:

vn = n · (vB(p̄) − vA(p̄))

Целевая скорость включает restitution при начальном vn < −1 и Baumgarte bias при penetration больше slop:

b = β max(penetration − slop, 0) / Δt
Δλn = Meff(n) [vtarget − vn + b],   λn ← max(0, λn + Δλn)

Импульсы −nΔλ и +nΔλ прикладываются к A и B. По двум ортогональным tangent-направлениям импульсы независимо clamp-ятся в [−μλn, +μλn]. Это квадратная аппроксимация кулоновского диска, а не общий cone solve.

Формулы реализованы inline в contact_solver.hpp:60–220.

Жизненный цикл: contacts_ очищается перед каждой детекцией, поэтому накопленные normal/tangent impulses не переживают следующий fixed step. Feature IDs из collision layer этот движок не использует; межкадрового manifold cache/warm start здесь нет.

7. Потребитель №2: FEM adapter → qopt

FEM-мир не создаёт gameplay PhysicsWorld. Перед каждым native substep он обновляет broad-phase позы, получает те же ContactPatch и отдельно преобразует их в qopt::Contact3D. Вызов находится непосредственно перед system_.step(): components.cpp:1858–1875.

7.1. Фильтрация и ownership endpoints

Каждый AttachedCollider сопоставляется с одним из видов endpoint: static world, maximal rigid body, floating articulation base или articulation link. Точка из world space переводится в локальную систему соответствующего тела/звена; qopt получает material point и больше не хранит collider/entity pointer. Реализация owner resolution: collision_contacts.cpp:137–213; world→local endpoints: 297–325.

До передачи отбрасываются disabled/layer-filtered colliders, static-static, self-collision одного dynamic endpoint, а по умолчанию также непосредственно соединённые bodies и соседние articulation links.

7.2. Runtime identity: group key и contact key

  • group_key строится из канонически упорядоченной пары адресов коллайдеров (ContactPatch::pair_key()).
  • feature_key = feature_a<<32 | feature_b; если feature IDs отсутствуют, используется индекс точки.
  • contact.key = hash(group_key, feature_key); локальные дубликаты разрешаются инкрементом ключа.

Ключ пары: contact_patch.cpp:88–105. Создание Contact3D: collision_contacts.cpp:392–431.

7.3. Persistence при временном geometric miss

Adapter передаёт qopt не только найденные контакты, но и список всех ещё допустимых live_groups. Если narrow phase на текущем substep полностью не вернул patch для живой пары, прежний контакт может быть временно удержан, когда одновременно выполнены условия:

  • его group всё ещё live и для группы нет свежих контактов;
  • предыдущий state был active и имел положительный normal impulse;
  • текущий gap материальных точек конечен и не превышает persistence_distance = 10⁻⁴.
gcurrent = n · (xB,current − xA,current) ≤ 10⁻⁴

Если свежий patch для этой группы появился, старый feature set не примешивается. Логика merge/persistence: contact3d.cpp:189–290; значение по умолчанию: contact3d.hpp:181–191.

7.4. Геометрия превращается в constraint row

При регистрации qopt фиксирует reference separation текущих material points. На последующих position/velocity итерациях gap обновляется без нового collision query:

g = g₀ + n · [(xB − xA) − (xB,ref − xA,ref)]
vn = n · (vB − vA)

Для generalized velocities v = Jq̇ нормальная строка собирается проекцией linear Jacobian каждого endpoint на n. Физический односторонний контракт:

n · (vB − vA) ≥ vmin,   λn ≥ 0

QP хранит эквивалентную строку Cv ≤ d, чтобы неотрицательный multiplier создавал −n на A и +n на B. В position projection limit равен signed gap; в velocity phase используется max(g,0)/Δt в принятой знаковой форме матрицы. Регистрация/reference separation: contact3d.cpp:428–503; обновление gap и сборка row: 571–668.

7.5. Warm start и friction

Состояние индексируется стабильным contact key. Предыдущий active contact с положительным impulse помечает соответствующую unilateral row как стартово активную; после solve сохраняются impulse, reaction и active flag. См. contact3d.cpp:839–902.

При μ > 0 для нормали строится детерминированный tangent basis, а friction assembly передаёт normal/tangent Jacobians, normal impulse и коэффициент μ. QP аппроксимирует кулоновский конус многоугольником; адаптер задаёт один уже скомбинированный коэффициент для всех scene contacts. Структура входа: contact3d.hpp:78–114; friction assembly: contact3d.cpp:687–780.

8. Параллельный выход через C API

tc_collision_world_detect_contacts() также вызывает C++ detect_contacts(), но преобразует patch в более бедный tc_contact_manifold:

  • collider pointers заменяются entity IDs, если это AttachedCollider;
  • передаётся общая normal A→B;
  • каждая пара endpoints схлопывается в midpoint;
  • feature IDs и отдельные pA/pB теряются;
  • не более четырёх точек.

Структура: tc_collision.h:67–97; конвертация: collision_world_c.cpp:74–135.

9. Инварианты и владельцы состояния

Collision layer владеет

  • world-space contact geometry;
  • normal A→B и signed-gap convention;
  • геометрическими feature IDs;
  • детерминированной редукцией patch.

Solver layer владеет

  • привязкой коллайдера к dynamic DOFs;
  • материалами, restitution/friction;
  • constraint rows и impulses;
  • active set, cache, warm start, persistence.

10. Ограничения и замеченные технические хвосты

  1. Многоточечный patch сейчас только у box-box. Sphere, capsule, convex hull и смешанные пары получают единственную точку, даже если физически контакт имеет площадь. Для qopt у них также нет настоящего feature ID.
  2. Box-box clipping не получает provenance лучшей SAT-оси. Генератор всегда выбирает reference face на A и incident face на B, хотя minimum-overlap axis может происходить от грани B или cross product рёбер. При edge-edge/face-B конфигурациях patch может быть менее точным; fallback возвращает одну SAT-точку. Кроме того, depth берётся относительно n_ref, а endpoint A сдвигается вдоль SAT normal. Signed-gap контракт сохраняется алгебраически, но pA не обязательно точно лежит на reference face, если направления различаются.
  3. Gameplay solver не использует feature identity и не делает межкадровый warm start. Это проще, но повышает jitter/число итераций по сравнению с qopt path.
  4. FEM contact identity процесс-локальна. pair_key() основан на адресах коллайдеров: подходит для runtime cache, но не для сериализации, воспроизводимых логов между запусками или сетевой идентичности.
  5. C API содержит терминологическую ловушку. Поле называется penetration, однако в него копируется signed_gap, то есть penetration имеет отрицательный знак. Комментарий это признаёт, но имя легко прочитать наоборот.
  6. C API storage глобален. s_manifold_storage — один static vector, поэтому результаты живут лишь до следующего вызова и API не рассчитан на параллельные независимые worlds.
Пункты 2, 5 и 6 — не утверждение о воспроизведённом баге в конкретной сцене, а архитектурные риски, непосредственно следующие из реализации. Пункт 2 особенно стоит проверять отдельными edge-edge и «best axis belongs to B» тестами перед развитием устойчивых box manifolds.
